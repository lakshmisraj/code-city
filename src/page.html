    What this is

    Code City draws a code repository as a city, so you can see its shape at a glance: where it starts, which files everything leans on, how its workflows run, and how it grew.

    Reading the city

    • Building = one file. Height = lines of code. Width = number of functions.
    • Districts = folders, raised one step per level.
    • Fire on a roof = TODO, FIXME or HACK comments.
    • Lit buildings show what the open panel is about: entry points and the file you picked, core files, answers and tour steps, search matches. Everything else dims.
    • Lines between buildings are imports: which file brings in which.
    • Hotspots colours each file by how many commits touched it, from dark blue (rarely) to orange-red (constantly), and lists the big files that keep changing, where bugs tend to live.

    Reading the panels

    • Code structure is read from the code itself, with no AI; tests, docs and examples aren't counted. Main paths go from each starting point the way the code goes; click a step to trace it. In How the parts connect each folder is a part: parts that use others come first, then the ones they rely on, then parts with no links to the rest. Point at a part to light its files.
    • Tangles are parts or files that import each other, so none of them can be changed or tested on its own. Imports inside functions, under if TYPE_CHECKING: or import type don't count, since they don't run when a file loads.
    • Hotspots are ranked by commits × lines: big files that keep changing, where bugs tend to cluster and refactoring pays off first.
    • Commits and branches: newest first; each lane is a line of work and a hollow dot is a merge. Click a commit to see what it changed in the city.
    • Explanations: select lines in a code window and press its Explain to explain just those (with nothing selected it explains the whole file); Explain the whole file at the top of that explanation does the rest. Names, files and line numbers in an explanation are clickable. Connections marked imports come from the code's import lines; inferred ones are Gemini's reading. Follow explains a connected file next.
    • Ask: Gemini picks the files from the repo's structure; explaining reads their code and opens it in its own window.
    • Workflows tour: the map shows every workflow at once, one colour each; the brightest buildings are files the workflows share. Gemini plans them from the README, imports and functions. Important lines come from Gemini reading the code; hand-off lines are the import lines that lead to the next step.

    Limits

    Without signing in, GitHub allows 60 requests an hour. Signing in raises it to 5,000 and unlocks Ask, tours and explanations, which have a daily limit per person.

    A quick look around, one part at a time.

    Start here

    • Repo: paste a public GitHub repo (or open a folder). Pick how much history to load, or keep today's files.
    • Understand › Code structure opens by itself: what the project says it is, where it starts, the most-used files, and how its parts connect.
    • Click any file to see its role, its functions, what it imports and what uses it. Explain this code reads it for you; View code opens it.
    • Trace next to a function follows what it calls, file to file, and what calls it. Click a name in a trace to open every step's code side by side. The Main paths in Code structure start you at the entry points.

    The tools

    • Ask (top bar): a question about the code; the files that answer it light up.
    • Understand: the Code structure (where it starts, the most-used files, main paths, how the parts connect, and tangles) and the workflows tour.
    • Find: a file by name.
    • Repo: also shows a pull request's changes on the city.
    • Commits and branches (Display, or the commit count in the top bar): the history as a graph, one lane per line of work, merges joining back. Click a commit to see what it changed; the city goes back to that moment when it's in the loaded history.
    • Display: colour by language, Hotspots (how often files change, with a ranked list) or imports; show or hide connections.
    • Trace (Python, JavaScript, TypeScript, Go): function-level links read with a parser, no AI. Each says how it was found: sure, self, likely, passes (a callback), or run time (where the trace has to stop).
    • Windows: explanations and code open in windows you can move, resize, fold to a tab and close. Follow on a connection explains the next file in the chain.

    Moving around

    • Drag to orbit, scroll (or pinch) to zoom, right-drag (or two fingers) to pan.
    • Click a building or a folder for details; shift-click a building to view its code.
    • Esc folds the front window, then closes the file panel, then the side panel.
    • Panels: click a rail icon again (or «) to fold the left panel; » folds a right panel. Drag a panel's edge to resize it.
